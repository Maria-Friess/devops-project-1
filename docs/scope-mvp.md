# Границы MVP и требования к продукту

## 1. Польза продукта

Сервис позволяет сохранять ссылки на статьи из разных источников и систематизировать их по категориям и статусам прочтения ("новые", "перечитать", "прочитано"). Пользователь получает возможность формирования своей персональной вэб-библиотеки.

## 2. Целевой пользователь

Человек, любящий порядок и часто читающий статьи в разных источниках.

## 3. Входит в MVP (in scope)

- [ ] Регистрация/вход (или анонимный доступ — решить)
- [ ] Запись новой статьи с присвоением категории, источником и статусом прочтения
- [ ] Изменение статуса и категории записи статьи 
- [ ] Удаление записи статьи.
- [ ] Основной сценарий: _TBD_
- [ ] Health endpoint `/health`
- [ ] Хранение данных в БД
- [ ] Запуск через Docker Compose
- [ ] CI: линт + тесты + сборка образа

## 4. Не входит (out of scope)

Явно перечислить, чтобы не расползался объём:

- мобильное приложение
- сложная аналитика и отчёты
- мультитенантность
- платежи
- ...

## 6. Нефункциональные требования

| Требование | Значение | Как проверяем |
|------------|----------|---------------|
| Доступность | 99% (учебно) | uptime-мониторинг |
| Время отклика p95 | < 500 ms | метрики приложения |
| Восстановление после сбоя | < 30 мин | restore drill |
| Резервное копирование | ежедневно, RPO 24 ч | проверка restore |

## 7. Критерии готовности MVP

- [ ] Приложение стабильно запускается локально по инструкции
- [ ] CI зелёный на каждом PR
- [ ] Образ автоматически публикуется в registry
- [ ] Деплой в облако воспроизводим (IaC + CD)
- [ ] Есть метрики, логи и минимум 2 алерта
- [ ] Бэкап проверен восстановлением
- [ ] README и документация позволяют пройти путь за 10 минут
